# Solar & Wind Deployment Intelligence Platform

## Database Design Document

## 1. Introduction

The Solar & Wind Deployment Intelligence Platform requires a structured database system to store user information, renewable energy projects, geographical sites, weather data, solar predictions, wind predictions, site suitability results, and generated reports.

PostgreSQL is used as the primary relational database management system.

PostGIS will later be used as a PostgreSQL extension to support geographical and spatial data such as coordinates, locations, and site boundaries.

---

`solar_wind_db`

## 4. Main Database Tables

The initial database design contains the following tables:

1. users
2. projects
3. sites
4. weather_data
5. solar_predictions
6. wind_predictions
7. suitability_results
8. reports

---

# 5. Users Table

## Purpose

The `users` table stores information about the users who access the Solar & Wind Deployment Intelligence Platform.

## Fields

| Column Name | Data Type | Description |
|---|---|---|
| id | SERIAL PRIMARY KEY | Unique identifier for each user |
| name | VARCHAR(100) | Name of the user |
| email | VARCHAR(150) UNIQUE | Email address of the user |
| password_hash | VARCHAR(255) | Securely stored password hash |
| role | VARCHAR(50) | Role of the user |
| created_at | TIMESTAMP | Date and time when the account was created |

## Possible User Roles

- Admin
- Analyst
- Viewer

---

# 6. Projects Table

## Purpose

The `projects` table stores renewable energy deployment projects created by users.

## Fields

| Column Name | Data Type | Description |
|---|---|---|
| id | SERIAL PRIMARY KEY | Unique project identifier |
| user_id | INTEGER FOREIGN KEY | User who created the project |
| project_name | VARCHAR(200) | Name of the project |
| description | TEXT | Project description |
| location | VARCHAR(255) | General project location |
| project_type | VARCHAR(50) | Solar, Wind, or Hybrid |
| status | VARCHAR(50) | Current project status |
| created_at | TIMESTAMP | Project creation date |

## Relationship

One user can create multiple projects.

Relationship:

`users → projects`

# 13. Database Relationships

The primary database relationships are:

`users → projects`

`projects → sites`

`projects → reports`

`sites → weather_data`

`sites → solar_predictions`

`sites → wind_predictions`

`sites → suitability_results`

---

# 14. Simplified Database Flow

User creates a project.

↓

Project contains one or more geographical sites.

↓

Weather and renewable energy data are collected for each site.

↓

Solar and wind prediction models analyze the site.

↓

The site suitability engine calculates suitability scores.

↓

Results are stored in the database.

↓

Reports are generated for the project.

---

# 15. Database Design Summary

The initial database architecture of the Solar & Wind Deployment Intelligence Platform has been designed using PostgreSQL.

The database contains tables for users, projects, sites, weather information, solar predictions, wind predictions, site suitability results, and reports.

The design provides a structured foundation for integrating the FastAPI backend, renewable energy datasets, machine learning prediction models, GIS analysis, and report generation features.

The database design may be extended during later development stages as additional project requirements and datasets are introduced.
